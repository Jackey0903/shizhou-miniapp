# 1.0.18 发布与验收记录

验证日期：2026-07-21

## 本版修复

- 支付套餐只允许四个已发布微信道具 ID 和固定价格，不再回退为内部套餐代码。
- 购买页只在订单状态为 `paid` 时显示支付成功；关闭、退款和下单失败不会误报成功。
- 支付失败记录增加小程序版本和运行环境，便于区分开发版、体验版和线上版。
- 管理员题库导入先整批校验再创建科目/题库，错误提示保留原 CSV 行号。
- 客户题库统一使用固定 CSV UTF-8 模板，重复导入自动跳过。

## 已完成验证

- 发布检查：119 个 JavaScript 文件语法检查与 17 组回归检查通过。
- 页面运行时扫描：39/39 页面通过，异常 0，控制台错误 0。
- 生产套餐：四个套餐的道具 ID、价格和业务页面映射一致。
- 微信道具：四个道具逐个重新上传并发布，`publish_status=2`。
- 生产预下单：督学试用返回 `sz_supervision_1d`、800 分和完整三项签名参数。
- 真实客户端记录：正确道具已成功拉起官方收银台，用户取消返回 `-2`；修复后未再出现 `PRODUCT_ID_NOT_PUBLISH`。
- 支付后端模拟：微信已支付查询、事务发权益、发货确认、重复同步幂等全部通过。
- 生产题库导入：临时新增 1 题、数量加 1、重复导入跳过、清理后数量恢复。
- 管理员资料/音频/壁纸非法上传：均拒绝且无脏数据写入。

## 最终真机验收

代码和后台配置无法代替用户确认扣款。正式发布前使用测试微信完成一笔 8 元督学试用订单，并核对：

1. 收银台显示“督学试用1日”和 8 元。
2. 支付后页面显示开通成功。
3. “我的订单”显示已支付、权益已发放。
4. 用户督学有效期增加 1 天，VIP/免广告有效期按套餐增加。
5. 云数据库订单为 `paid`，`benefitsGranted=true`，发货状态为 `confirmed` 或 `notified`。

未完成真实扣款前，不应对外宣称支付闭环已经完成真金白银验收。
